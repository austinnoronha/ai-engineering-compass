# Contributing to AI Engineering Compass

Thanks for helping make this a useful place for engineers to learn from one another. Contributions can be small: fix an unclear sentence, improve an example, add a reference, or propose a new topic.

## Start with an issue

For a substantial new article or example, open an issue first. Describe the problem, intended audience, and what a reader should be able to understand or do afterward. Small corrections can go directly into a pull request.

## What makes a good contribution

- Practical guidance grounded in sound engineering reasoning.
- Clear scope and assumptions.
- Examples that are accurate and runnable where practical.
- Trade-offs and situations where the recommendation does not fit.
- References to primary or authoritative sources.
- Respect for privacy, security, and third-party licenses.

Do not include company-confidential material, customer information, credentials, internal incident details, or private source code. Generalize lessons and remove identifying details before sharing.

## Article structure

Use [the article template](templates/article-template.md). Each article should identify:

- Status: Recommended, Exploratory, or Deprecated.
- Last reviewed date.
- Scope, including relevant versions or platforms.
- Problem, rationale, practices, example, and trade-offs.
- Verification or review checklist.
- Further reading.

Status meanings:

- **Recommended:** broadly useful guidance with a clear scope and supporting rationale.
- **Exploratory:** an emerging approach or idea that needs more experience or validation.
- **Deprecated:** no longer recommended for new work; explain why and link to a replacement where possible.

## Evidence and references

Prefer official documentation, standards, source code, and primary research. Check that links work and that referenced behaviour applies to the stated versions. Cite sources near the claim they support. Do not fabricate citations or imply that an example has been tested when it has not.

## Code examples

Keep examples focused and self-contained. Include prerequisites and run/test instructions. Use safe sample data and fake credentials. Original code samples are licensed under MIT; documentation is licensed under CC BY 4.0. Third-party content keeps its original license and must be compatible with the contribution.

## Using the project logo

Contributors are welcome to use the AI Engineering Compass logo in their pull requests, articles, tutorials, slides, and other material that references or contributes to this project.

- Use the original SVG assets from [assets/brand](assets/brand/).
- Follow the [brand guidelines](docs/brand-guidelines.md) for sizing, colour, backgrounds, and clear space.
- Credit **AI Engineering Compass** and link to this repository or [LICENSE-BRAND](LICENSE-BRAND).
- If you modify the logo, indicate that it has been modified and retain the required attribution.
- Do not use the logo to imply endorsement, official maintainer status, or an affiliation that does not exist.

The logo artwork is shared under CC BY 4.0. This permission is separate from the MIT license for code and CC BY 4.0 license for written documentation.

## Pull requests

- Keep one coherent purpose per pull request.
- Explain the problem and the proposed change.
- Include verification evidence.
- Call out version assumptions and known limitations.
- Check spelling, Markdown formatting, links, and relative paths.
- Update topic indexes when adding a new article.

Use the [pull request template](.github/PULL_REQUEST_TEMPLATE.md).

## Review

Reviewers should focus on accuracy, clarity, relevance, attribution, privacy, security, and maintainability. Suggestions should explain the concern and, where possible, a path to improve the contribution.

By submitting a contribution, you agree that your original documentation is shared under CC BY 4.0 and original code under MIT, consistent with the relevant license notices.
